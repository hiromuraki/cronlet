## [P2] 探测读到首行后停止读取 stdout，后续输出会阻塞进程 —— 已修复

复述：`ReadLineAsync` 收到第一行就完成，剩余 stdout 没有消费者，子进程写满管道后阻塞，探测只能等满 10 秒超时。stderr 仍然 `ReadToEndAsync`，8 MiB 错误输出带来约 32.6 MiB 托管分配。

修复（[ShellResolver.cs](../src/Cronlet/ShellResolver.cs)）：两路管道都换成"读到底、只留前 N 个字符"的 `DrainAsync`。

```csharp
private static async Task<string> DrainAsync(StreamReader reader, int keep)
{
    var buffer = new char[4096];
    var kept = new StringBuilder(keep);

    int read;
    while ((read = await reader.ReadAsync(buffer).ConfigureAwait(false)) > 0)
    {
        int room = keep - kept.Length;
        if (room > 0) kept.Append(buffer, 0, Math.Min(room, read));
    }

    return kept.ToString();
}
```

- 一直读到流结束，所以写满管道的子进程不会把自己堵死；
- 只保留 stdout 前 256 字符（判版本用首行）与 stderr 前 2048 字符（诊断用），内存有界；
- 进程退出与两路读取继续共用同一个截止时间，超时后 `Kill(true)` 让流结束。

## [P2] 重载期间退出可遗留正在运行的探测进程 —— 已修复

复述：重载把校验移到后台，但没把退出信号传下去；探测进程不在调度器进程集合里，也不在 Job 中，宿主退出后它会继续跑。

修复：

- `ShellResolver.Probe(path, CancellationToken)`：等待改为 `all.Wait(ProbeTimeout, ct)`，取消时立即 `Kill(true)` 并返回失败。
- `ConfigValidator.Validate(config, CancellationToken)` 一路转发到探测；托盘重载传 `cts.Token`（[Program.cs](../src/Cronlet/Program.cs)），退出时 `cts.Cancel()` 会打断等待并终止探测。
- 探测进程也加入 Job：`ChildJob.TryAssign(proc, out _)`，宿主被强杀时由 Job 的 `KILL_ON_JOB_CLOSE` 兜底清理。

## [P3] 逐簇截断仍可能复制一个即将丢弃的超长字形簇 —— 已修复

修复（[Log.cs](../src/Cronlet/Log.cs)）：改用 span 版 API，不再为每个簇生成子字符串。

```csharp
ReadOnlySpan<char> rest = line.AsSpan();
while (!rest.IsEmpty)
{
    int length = StringInfo.GetNextTextElementLength(rest);
    int size = Encoding.UTF8.GetByteCount(rest[..length]);
    if (used + size > MaxLineBytes) break;
    used += size;
    cut += length;
    rest = rest[length..];
}
```

字形簇语义与 UTF-8 预算不变，超长簇在判定阶段不再被复制。
