## 审查发现

### [P2] 配置重载成功后仍会执行旧命令

位置 [Scheduler.cs 第 340–352 行](../src/Cronlet/Scheduler.cs#L340-L352)

旧任务使用 `overlap = "queue"` 并积压一次运行时，完成回调先把运行计数减到零，再尝试补跑。重载可以在两步之间替换配置。补跑只按名称检查任务是否仍启用，随后传给 `Fire` 的仍是旧任务配置。已复现同名任务重载返回成功后，旧命令再次启动。

将补跑与重载置于同一同步边界，并校验任务所属的配置版本。

### [P2] PowerShell 命令失败时可能记录退出码 0

位置 [Scheduler.cs 第 389–396 行](../src/Cronlet/Scheduler.cs#L389-L396)

内联命令和文件分支都用 `exit $LASTEXITCODE` 决定退出码。该变量无法反映 PowerShell cmdlet 的非终止错误。使用当前包装执行 `Get-Item` 访问不存在的路径时，PowerShell 输出错误，子进程仍退出 0。

保留原生程序的退出码，并将 PowerShell 执行失败映射为非零退出码。

### [P2] 含 URL 或路径参数的合法命令被拒绝

位置 [ScriptResolver.cs 第 25–32 行](../src/Cronlet/ScriptResolver.cs#L25-L32)

路径检测将任何含斜杠的字符串视为文件路径。已复现 `Invoke-WebRequest https://example.com` 在配置校验时被报为脚本不存在，导致使用这份配置启动或重载失败。

区分独立的脚本路径与带参数的 PowerShell 命令。

### [P2] 日志轮转会把半行 JSON 写回文件

位置 [Log.cs 第 104–117 行](../src/Cronlet/Log.cs#L104-L117)

当末尾 8 MiB 只包含一条超长日志的后半段时，唯一的换行符位于最后一个字节，当前条件会把截断的记录原样写回。已用一条 16 MiB 的 stdout 复现，轮转后的首行无法解析为 JSON。

只保留完整的日志记录。当保留窗口中没有完整记录时，将裁剪结果置空。

### [P3] 超大 timeout 通过校验后在子进程启动后抛错

位置 [Scheduler.cs 第 281–295 行](../src/Cronlet/Scheduler.cs#L281-L295)

已验证 `timeout = 5000000` 可以通过配置校验，但用该值创建计时器会抛出 `ArgumentOutOfRangeException`。调度器在创建计时器前已启动 PowerShell。异常路径会清除调度状态，后续触发可能与仍在执行的任务重叠。

在启动子进程前拒绝超出计时器范围的超时值。
