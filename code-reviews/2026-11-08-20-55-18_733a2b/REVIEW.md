## 发现

### [P2] 旧补跑可在重载后提前触发同名新任务

[Scheduler.cs 第 87–102 行](../../src/Cronlet/Scheduler.cs#L87-L102) · [第 346–392 行](../../src/Cronlet/Scheduler.cs#L346-L392)

任务结束时先递减 `_running` 并通知重载空闲，随后才提交补跑请求。若重载先完成，补跑就按名称找到新任务并立即派发。我用真实子进程和受控的重载续体复现：旧任务的第二次触发被排队，随后成功重载同名任务，新任务在 cron 到期前就输出了 `new-payload`。

另外，超时分支恢复补跑与清除 `_reloading` 分属两个临界区。代码路径显示，期间新登记的补跑可滞留在集合中，错过本次恢复。该超时交错未做集成复现。

将运行计数、补跑登记及重载结果归入同一次调度状态更新。旧请求应绑定原任务实例或配置版本，重载成功后只保留新配置的计划触发。

### [P2] 命令参数以脚本扩展名结尾时校验失败

[ScriptResolver.cs 第 33–40 行](../../src/Cronlet/ScriptResolver.cs#L33-L40) · [ConfigValidator.cs 第 29–30 行](../../src/Cronlet/ConfigValidator.cs#L29-L30)

文件查找未命中时，扩展名判断早于命令形态判断。实测 `Write-Output report.ps1` 和 PowerShell 字符串表达式 `'report.ps1'` 都被报为脚本不存在。含空格且已存在的脚本路径仍应能执行，因此简单地把空白判断移回扩展名判断之前，只会改变猜测规则。

为命令提供显式入口。旧配置的兼容分支应保留已存在文件的优先级，并缩小缺失文件诊断的适用范围。

### [P2] 脚本在校验后消失会改变执行方式

[ConfigValidator.cs 第 29–30 行](../../src/Cronlet/ConfigValidator.cs#L29-L30) · [Scheduler.cs 第 430–439 行](../../src/Cronlet/Scheduler.cs#L430-L439)

校验和派发分别解析 `script`，派发时根据最新文件状态重新决定执行类型。实测让配置引用名为 `Write-Output ready.ps1` 的现有脚本，校验成功后删除该文件。下一次启动参数把原配置值作为内联命令执行，输出 `ready.ps1` 并退出 0，日志因此无法反映已配置的脚本消失。

在启动及重载时固定执行类型和解析后的脚本路径。路径失效时记录任务失败，保持执行类型。

### [P3] 启用原生命令错误处理后会丢失原生退出码

[CommandWrapper.cs 第 22–26 行](../../src/Cronlet/CommandWrapper.cs#L22-L26)

当任务显式设置 `$PSNativeCommandUseErrorActionPreference = $true`，非零退出会先进入通用 `catch`。实测 `cmd.exe /c exit 7` 的退出码被改为 1，与包装器承诺的原生退出码透传不符。也已确认该异常携带 `ExitCode = 7`。

在通用错误处理之前识别原生退出异常并保留其退出码。回归用例覆盖原生命令错误处理开启及关闭两种情况。

## 实现方案比较

| 领域 | 当前做法及代价 | 建议 |
| --- | --- | --- |
| 调度和重载 | 启动派发已由 `_queueGate` 保护。完成登记、空闲通知、补跑和配置切换仍分散在不同锁区间，局部补锁需要继续证明多个交错。 | 首选单一调度状态锁。完成时在锁内处理旧请求并发布空闲，重载成功时原子替换配置并废弃旧请求，超时时原子恢复旧请求和派发。实际进程启动、等待与日志写入放在状态更新之外，派发名额先在锁内登记。事件循环也能串行化这些变化，但要改写唤醒、停止和进程回调，对当前规模成本更高。 |
| 配置解析 | 文件优先兼容了含空格的旧路径。继续扩展字符规则能修复个别样例，但合法文件名与 PowerShell 表达式存在重叠。 | 加载后生成一次明确的执行描述，供校验、排程和启动共用。近期可沿用旧配置字段并收窄猜测规则，长期可提供互斥的 `script_file` 与 `command`，旧 `script` 保留为兼容入口。显式字段增加配置选项，但允许准确诊断缺失文件，且无需为每类命令调整规则。 |
| PowerShell 包装 | 独立行边界已解决行尾注释问题。失败即停提供了明确退出码，同时会中断原先允许继续的非终止错误。 | 保留当前换行结构，并明确记录失败即停的行为和例外。区分 PowerShell 错误与原生退出异常即可修复已复现的问题。若后续需要支持完整的 PowerShell 脚本结构，再评估独立解析命令体；这会涉及作用域和参数语义。 |
| 构建约束 | 分析器与警告升级集中在 `Directory.Build.props`。隔离探针确认了 `CA1305` 和 `IDE0005` 能阻止构建。CI 当前选择预览 SDK 的版本范围。 | 保留集中配置。如果希望同一提交可稳定复现编译与分析结果，可让 CI 和 `global.json` 共用明确的 SDK 版本，并通过独立变更升级。滚动跟随 SDK 可以更早发现新规则，代价是同一提交的验证结果可能随 SDK 改变。 |

调度回归测试宜控制任务完成和重载超时的时序，覆盖旧任务退出、同名新任务按时触发，以及超时后旧补跑恰好恢复一次。可控的进程完成信号和超时信号可以替代真实的 30 秒等待。
