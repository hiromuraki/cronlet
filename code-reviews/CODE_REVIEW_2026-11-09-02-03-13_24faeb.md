### [P2] 轮转直接覆盖原文件，中断可能损坏历史日志

[Log.cs 第 88–125 行](../src/Cronlet/Log.cs#L88-L125)

普通输出确实走追加，但轮转先调用 `File.WriteAllBytes(path, ...)` 覆盖原文件，之后才追加本次记录。定向验证在轮转前以共享方式打开原文件。轮转后，已有句柄看到原文件从 16,777,217 字节缩为 8,388,718 字节，确认现有文件被改写。若进程在截断到写完期间被强制终止，损失可涉及全部保留记录，并可能留下半行。未在写入中间强杀进程，后果依据写入路径判断。

先将保留记录写入同目录的临时文件，写完后再替换原文件。若替换因文件被占用而失败，保留原文件并记录轮转失败。

### [P3] 输出截断以 UTF-16 码元计数，且可能切断字符

[Log.cs 第 21–24 行](../src/Cronlet/Log.cs#L21-L24) · [第 47–67 行](../src/Cronlet/Log.cs#L47-L67) · [README.md 第 70–71 行](../README.md#L70-L71)

README 写的是 8 KiB，代码按 `string.Length` 计数并直接切片。实测 4,096 个 `作` 字写入后，输出内容占 12,288 个 UTF-8 字节，未附截断标记。若 emoji 横跨第 8,192 个码元，截断后 JSON 中会出现替换字符 `�`。

如果上限按 UTF-8 字节定义，按完整 Unicode 标量计算前缀，并明确该上限是否包含截断标记、JSON 转义和记录元数据。如果采用字符上限，应同步调整文档，并在完整字符边界截断。

## 方案评估

- **日志轮转**：保留窗口前一字节的判定。实际超过 16 MiB 的日志触发轮转后，对齐行首的完整 8 MiB 记录已保留。建议将裁剪和文件替换分开验证，分别覆盖保留范围与写入失败。一次性替换会多写一个临时文件，换取进程中断时保留原始日志。
- **PowerShell**：保留配置生效时解析路径、派发复用的方案。一次有超时的执行检查比校验 PE 文件头覆盖更多实际失败，例如文件格式错误或宿主初始化失败，但会增加启用任务时的启动或重载开销。
- **输出边界**：若目标只是避免单条日志占满轮转窗口，保留有界输出即可。若对外承诺 8 KiB，应选定明确的字节口径。当前截断发生在完整行进入回调之后，因此它限制日志保留量，无法限制读取巨行时的峰值内存。
