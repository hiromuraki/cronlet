[ShellResolver.cs 第 65–104 行](../src/Cronlet/ShellResolver.cs#L65-L104) · [第 135–148 行](../src/Cronlet/ShellResolver.cs#L135-L148) · [Program.cs 第 81–93 行](../src/Cronlet/Program.cs#L81-L93)

`Probe` 在检查取消之前已经调用 `Process.Start`。传入已取消的令牌及不存在的可执行文件，实测得到文件找不到，说明仍尝试启动。两个 `DrainAsync` 都不接收取消令牌，超时或取消后直接返回，依赖终止进程使管道结束。如果管道仍被后代持有，读取可能继续。用同一运行时验证，直接取得 `StandardOutput` 并发起读取后，仅释放 `Process` 对象，读取在子进程继续运行时仍处于等待状态。该验证证明了释放边界，未复现真实托盘退出后的后代残留。

启动前检查取消，用关联的截止时间约束等待和两路读取。超时与取消共用一处清理，明确释放读取端并观察读任务结束。已运行探测收到取消时的主进程终止已经实测通过。

## 实测资源占用

使用同一台 Windows x64 主机上的 Release 单文件发布产物，.NET SDK 11.0.100 RC3、PowerShell 7.6.7。各场景使用独立临时目录和配置。工作集含共享页，私有提交表示进程的私有提交内存。两者不能相加，也不能把宿主与子进程的工作集相加当作实际物理占用。

### 无界面空闲

启动后等 2 秒，每秒采样一次，共 14.2 秒。带任务场景使用远期 cron，PowerShell 配置探测已结束。

| 场景 | 工作集中位数 | 私有提交中位数 | 期末线程 / 句柄 | CPU 时间增量 |
| --- | ---: | ---: | ---: | ---: |
| 无任务 | 35.4 MiB | 9.4 MiB | 11 / 245 | 0 ms |
| 一个远期任务 | 39.8 MiB | 10.9 MiB | 18 / 292 | 0 ms |

窗口短于 30–60 秒的调度等待上限，因此只说明该窗口没有测到 CPU 时间增量。唤醒、长期内存和托盘模式需另测。

### 自然派发的任务

两个无界面实例在同一分钟各派发一个任务。每约 90 ms 采样一次。两个命令均在写完输出后休眠 5 秒，便于观察子进程。记录的峰值是采样峰值，PowerShell CPU 时间为最后可观测的累计值。

| 场景 | 宿主峰值工作集 / 私有提交 | 宿主 CPU 时间增量 | PowerShell 峰值工作集 / 私有提交 | PowerShell 可观测 CPU | 任务日志 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 单行输出 | 40.6 / 11.0 MiB | 62.5 ms | 88.0 / 28.8 MiB | 1,140.6 ms | 1 行，109 字节 |
| 突发输出 | 57.4 / 25.6 MiB | 4,312.5 ms | 101.0 / 39.1 MiB | 1,875.0 ms | 4,002 行，896,216 字节 |

突发场景首末日志相隔 3.595 秒。任务完成后约 1.5 秒，宿主仍有 52.1 MiB 工作集、21.3 MiB 私有提交。这是一次短期高水位观测，不能据此认定泄露。低输出任务的主要开销在 PowerShell，突发场景则显示宿主处理日志的开销值得单独优化。当前结果没有分解 JSON 序列化、线程调度和文件 I/O 的占比。

## 优化顺序

| 优先级 | 场景与改动 | 收益与取舍 |
| --- | --- | --- |
| 1 | 无界面模式跳过 WinForms 初始化。 | 改动小，已测得约 2.93 MiB 工作集、0.55 MiB 私有提交和 7 个句柄的差异。保留交互模式的初始化，补测托盘。 |
| 2 | 高频低输出任务优先减少 PowerShell 启动次数。 | 子进程比空闲宿主占用更多内存和 CPU。仅在命令具有相同调度和故障语义时合并执行。长期常驻 PowerShell 会抬高空闲占用，并涉及任务状态隔离。 |
| 3 | 对高输出任务使用有界批量追加，降低每行打开文件和检查轮转的次数。 | 4,002 行场景给出了值得优化的宿主 CPU 基线。当前每行都进入全局锁、检查文件大小并打开文件。可按小批次和短时间间隔刷新，任务结束时补刷。需要明确强制终止时可丢失的最后一批记录范围。收益应以相同负载做对照测试。[Log.cs 第 47–60 行](../src/Cronlet/Log.cs#L47-L60) · [第 113–119 行](../src/Cronlet/Log.cs#L113-L119) |
| 4 | 将轮转改为有界缓冲区复制。 | 先确定完整记录的起止位置，再分块复制到同目录临时文件并替换。避免同时构造窗口和多个副本，保持现有行边界及替换语义。 |
| 5 | 空队列直接等唤醒，保留有计划时的时钟重查。 | 可减少空配置的周期唤醒。短窗口内已有低空闲 CPU，优先级低于前四项。若进一步改为一次睡到远期触发，需处理系统时钟跳变。[Scheduler.cs 第 147–180 行](../src/Cronlet/Scheduler.cs#L147-L180) |

若部署目标主要是减少空闲物理内存，先采用低成本的无界面初始化分离，并在实际部署账户下复测。若仍需明显低于当前宿主基线，再单独评估不加载桌面运行时的无界面构建，其收益本轮未测。输出截断目前发生在完整行回调之后，极端单行的读取内存仍由行缓冲决定。
