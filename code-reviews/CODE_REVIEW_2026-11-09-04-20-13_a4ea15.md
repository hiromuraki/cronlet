## 发现

### [P1] 主分支的合法配置会被拒绝或被改写

[Config.cs 第 76–79 行](../src/Cronlet/Config.cs#L76-L79) · [TomlConfig.cs 第 14–53 行](../src/Cronlet/TomlConfig.cs#L14-L53) · [第 103–144 行](../src/Cronlet/TomlConfig.cs#L103-L144)

新解析器按行拆分并只识别有限的键和值。用主分支的 Tomlyn 2.11.0 和同形配置模型对照，`tasks = []`、三引号多行命令、`\u4f5c` 和 `jitter = 1_000` 原本可加载，分支均拒绝。单行三引号命令的情况更隐蔽：分支接受它，却给命令内容保留多余的引号。升级可能让已有配置无法启动，或使实际传给 PowerShell 的内容发生变化。

优先保留 Tomlyn 并改用生成的序列化元数据。用同版本关闭反射后，本地探针已验证空任务列表和多行命令可加载，未验证该变体的原生链接。如果子集是明确的产品决定，应公布兼容范围并拒绝会被误解的语法。 [Tomlyn 源生成文档](https://xoofx.github.io/Tomlyn/docs/source-generation/) · [TOML 1.1 规范](https://toml.io/en/v1.1.0)

### [P2] 托盘取消与显式释放竞争，正常退出可变成启动失败

[Program.cs 第 67–109 行](../src/Cronlet/Program.cs#L67-L109) · [TrayContext.cs 第 29–42 行](../src/Cronlet/TrayContext.cs#L29-L42) · [第 100 行](../src/Cronlet/TrayContext.cs#L100)

点击退出时，应用取消传给 DotTray 的令牌，主线程醒来后又调用 `Dispose()`。检查本地 DotTray 3.0.0 程序集发现，令牌回调向托盘窗口投递 `WM_CLOSE`，窗口处理会销毁窗口。显式 `Dispose()` 会再次投递 `WM_CLOSE`，且在检查线程状态前就会对投递失败抛异常。定向调用已确认，DotTray 对失效窗口执行 `Dispose()` 时抛 `Win32Exception(1400)`。若窗口先完成关闭，Cronlet 会捕获该异常、记录 `fatal` 并按启动失败返回。未在真实托盘上手动触发此竞争。

让托盘只走一条关闭路径。可以用应用令牌通知调度器退出，由主线程独自释放 DotTray 实例。

### [P2] 新解析器会接受并执行原本非法的配置

[TomlConfig.cs 第 36–52 行](../src/Cronlet/TomlConfig.cs#L36-L52) · [第 58–71 行](../src/Cronlet/TomlConfig.cs#L58-L71) · [第 103–112 行](../src/Cronlet/TomlConfig.cs#L103-L112)

键赋值未检查重复，字符串只检查首尾引号。实测同一任务先写 `enabled = false`、再写 `enabled = true`，Tomlyn 拒绝，分支却启用任务。未正确转义的 `command = "Write-Output "ok""` 也从解析错误变成可执行命令。这会让应当拒绝的配置重载生效。

保留成熟解析器的语法检查，或在子集内显式拒绝重复键、未转义的闭合引号及字符串后的额外内容。 [TOML 1.1 规范](https://toml.io/en/v1.1.0)

### [P2] AOT Release 的新标签默认指向主分支

[build.yml 第 56–65 行](../.github/workflows/build.yml#L56-L65)

二进制由 `try/dottray` 的检出提交构建，发布命令却只给出新标签名。按 GitHub CLI 行为，标签不存在且未指定目标时会从默认分支创建。因此 Release 中的源代码标签可能与二进制及说明中的 SHA 不同。此结论来自工作流和 CLI 行为，未创建测试 Release。

将标签目标设为工作流检出的完整 SHA，或使用已指向该 SHA 的标签并校验其存在。实验发布也可明确标为预发行，避免影响正式版本的最新发行标记。 [GitHub CLI 发布文档](https://cli.github.com/manual/gh_release_create)

### [P3] 托盘菜单和启动失败图标没有完整的释放路径

[TrayContext.cs 第 13–14 行](../src/Cronlet/TrayContext.cs#L13-L14) · [第 100 行](../src/Cronlet/TrayContext.cs#L100) · [Program.cs 第 115–125 行](../src/Cronlet/Program.cs#L115-L125)

正常托盘创建了可释放的菜单处理器，但只释放图标。DotTray 3.0.0 的图标释放与窗口线程清理都没有释放处理器，处理器自己的释放会解除事件订阅并释放信号量。临时错误托盘虽然会释放菜单，但 `NotifyIcon.Run` 抛异常时跳过了原始 HICON 的释放。

由 `TrayContext` 在图标关闭后释放菜单处理器，并把临时 HICON 的释放放到 `finally`。 [DotTray 用法](https://github.com/BlyZeDev/DotTray#1-quickstart)

## 资源对照与实现取舍

主分支和实验分支均使用本机 Release、依赖运行时的单文件产物。每版交替启动四次，以无任务的 `--headless` 配置运行，启动日志出现约一秒后采样。

| 指标 | 主分支 | 实验分支 |
| --- | ---: | ---: |
| EXE 大小 | 591,714 字节 | 289,124 字节 |
| 工作集中位数 | 36.21 MiB | 29.26 MiB |
| 私有提交中位数 | 9.57 MiB | 7.50 MiB |
| 线程 / 句柄 | 12 / 246 | 15 / 251 |

实验分支的文件和无界面内存均更小。改动同时涉及去除 WinForms、去掉 Tomlyn 和更换 JSON 写入，不能将差异单独归因于 DotTray。托盘模式与 NativeAOT 的实际资源占用仍待测。

建议保留 DotTray 作为独立托盘替换，先补齐退出所有权。配置解析可保留 Tomlyn 的源生成路径，JSONL 可选用直接写入 UTF-8 的 `Utf8JsonWriter` 来避免反射与手写转义。是否保留手写实现，宜由同条件的 AOT 体积和运行对照决定。 [Tomlyn 源生成文档](https://xoofx.github.io/Tomlyn/docs/source-generation/) · [Utf8JsonWriter 文档](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/use-utf8jsonwriter)
