## [P1] 随机抖动退化为固定延迟 —— 已修复

这是我在 `c26604e` 引入的回归。原来入队时取 `Random.Shared.Next(0, jitter + 1)`；改成按间隔截断后，我直接用了 `ClampJitter` 的返回值——它是**上限**，不是抽样结果，于是每次触发都被固定在"名义时间 + 上限"。

修复（[Scheduler.cs](../src/Cronlet/Scheduler.cs)）：把上限计算与抽样拆开。

```csharp
int limit = ClampJitter(task.jitter, nominal.Value, nextNominal);
_queue.Enqueue(task, nominal.Value.AddSeconds(PickJitter(limit)));
```

```csharp
internal static int PickJitter(int limit, Random? random = null)
{
    if (limit <= 0) return 0;
    return (random ?? Random.Shared).Next(0, limit + 1);
}
```

随机源可注入，测试不再只盯上限：

- `PickJitter_uses_the_random_source`：注入 `FixedRandom` 分别验证 0、中间值 5、上限 10 三种取值；
- `PickJitter_varies_across_calls`：50 次调用必须出现多个不同值（防止再退化成固定值）；
- `PickJitter_is_zero_without_room`：上限为 0 时直接返回 0。

运行观察：部署后第一次触发是 `00:40:04.074`（+4 秒），不再是 `jitter = 5` 时的固定 +5 秒。

## [P2] 子进程可在父进程加入 Job 前脱离清理范围 —— 采纳"尽力清理 + 记录失败"

审查给了两条路：先绑定 Job 再允许命令执行（需要自管 `CreateProcess` 与句柄），或承认是尽力清理并记录失败。选后者。

修复（[ChildJob.cs](../src/Cronlet/ChildJob.cs) · [Scheduler.cs](../src/Cronlet/Scheduler.cs)）：

- `ChildJob.Assign` 改为 `TryAssign(Process, out string? error)`：创建 Job、设置 `KILL_ON_JOB_CLOSE`、`AssignProcessToJobObject` 三处失败都会带出原因（含 `Marshal.GetLastWin32Error()`），静态构造期的失败被保存到 `InitError`。
- 调度器在分配失败时记一条 `job-assign-failed`，用 `Interlocked.Exchange` 保证整个过程只记一次，不会每个任务刷一行。
- 类注释写明覆盖范围：只覆盖加入 Job 之后的进程，`Start()` 与 `TryAssign` 之间派生的后代可能逃逸。

未选择挂起启动的原因：需要在启动层自己调用 `CreateProcess`（`CREATE_SUSPENDED`）、管理主线程句柄、处理 `ResumeThread` 失败路径，而当前收益只覆盖"强杀"这一个场景——正常退出走 `Stop()` 显式 `Kill(entireProcessTree)`，不依赖 Job。

## [P2] 过长任务名通过校验后导致输出丢失 —— 已修复（按仓库要求收紧）

按你的要求，任务名限制为 **128 个字符**、仅允许**大小写字母 + 数字 + 下划线 + 短横线**（[ConfigValidator.cs](../src/Cronlet/ConfigValidator.cs)）。

这条同时也消灭了审查发现的两个隐患：

- 260 字母的名字不再可能通过校验，日志文件名长度有界（`task-` + 128 + `.jsonl`）；
- 字符集限制后，任务名到日志文件名的映射是恒等的，`a/b` 与 `a_b` 这类冲突不可能再发生。因此删掉了上一轮加的文件名查重，`Log.TaskFileName` 也从"逐字符替换"简化为直接拼接。

校验顺序：name 非空 → 字符集与长度 → 大小写不敏感重名 → 其余字段。

错误信息：`任务 <name>: name 只能包含字母、数字、下划线和短横线，且不超过 128 个字符`。

## 方案评估的回应

| 领域 | 处理 |
| --- | --- |
| 排程 | 采纳"上限计算、抽样、入队分开"。队列同时保存名义时间与实际到期时间、系统休眠后的漏触发策略，本轮不做——当前策略是"醒来后按 `GetNextOccurrence(UtcNow)` 重排"，跳过的触发不会补跑 |
| 进程 | 采纳"记录失败 + 明确覆盖范围"，不做先绑定再执行 |
| 日志 | 采用"配置拒绝长名称"，不引入长度有界的编码文件名，避免改变历史日志路径 |
